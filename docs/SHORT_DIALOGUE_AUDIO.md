# 짧은 받아쓰기와 원본 문장 음성

2026-09-30 · 콘텐츠 버전 `2026.09.30-1`

## 구간 길이 재수정

사용자 피드백에 따라 15–30초 문단을 폐기하고 약 5–15초의 짧은 대화로 다시 생성했다. 현재 84개 영상에 선택 가능한 구간 3,216개가 있다. 목표 길이를 맞추려고 사용자가 지정한 구문을 다시 합치지 않는다.

Faceytalk은 사용자가 제공한 Chapter와 대화 시각을 우선한다. Chapter 1은 26–65초의 대화 6개, Chapter 2는 현재 확인된 65–104초의 대화 5개다. 첫 구간의 `Uss!`가 기존 캡처에서 33–34초여서 다음 구간과 1초 겹치며, 원본 참조와 미검증 시각 표시를 유지한다. 재생과 받아쓰기에는 동일한 구간 전체를 사용한다. 실제 음성과 초 단위 경계를 전수 대조했다고 주장하지 않는다.

명시 구간은 `content/transcript-groups.json`에 보존한다. 나머지는 원본 cue를 추가로 쪼개지 않고 문장부호·쉼을 참고해 묶는다. 원본 자동 자막 자체가 문장 중간에 끊긴 경우까지 완결된 문장 경계를 보장하지는 않는다.

## Chapter 확인 상태

사용자가 제공한 Chapter 1 `Facey talk initiates`는 26–65초 경계와 대화 6개를 반영한다. Chapter 2 `Sharing struggles`는 65초 시작과 104초까지의 대화 5개를 반영한다. `content/chapter-metadata.json`과 대본 자료에 사용자 제공 범위와 출처를 기록한다. Chapter 1은 제공된 다음 Chapter 시작 시각으로 끝을 확인했으며, Chapter 2는 104초 이후 실제 끝이 아직 확인되지 않은 발췌다.

로컬 캡처 대본에는 대화 타임스탬프가 있지만 YouTube 화면에서 보이는 Chapter 제목 전체가 들어 있지 않다. 프로그램은 대본 파일의 명시적 Chapter/챕터 제목을 읽을 수 있고, 사용자가 제공한 제목과 시각도 같은 구조로 반영한다. 다만 일반 자막 cue만으로 공식 Chapter 경계를 추측하지 않는다. 이 영상은 총 7개 Chapter라고 알려져 있으나 현재 확인된 것은 Chapter 1과 Chapter 2의 시작뿐이다. 104초 이후는 번호 없는 `목차 확인 중` 아래에서 계속 연습할 수 있으며, Chapter 2의 실제 끝과 남은 5개 제목·시각이 확인되기 전에는 7개 구분이 완료됐다고 표시하지 않는다.

기존 다른 영상의 대본 목차와 Cubby 제목 보정은 유지한다. 생성된 목차에는 전체 영상·도입부·미확인 나머지 영역도 포함될 수 있으므로 모두 공식 YouTube Chapter라는 뜻은 아니다.

## Chapter 먼저 보기

Chapter를 선택하면 그 범위를 대화 사이에서 멈추지 않고 먼저 재생한다. 범위가 끝나면 해당 Chapter를 시청한 것으로 저장하고 첫 대화의 듣기 단계로 이동한다. 재생 완료를 기술적으로 확인할 수 없거나 이미 함께 시청한 경우에는 `시청했어요 · 대화 학습 시작` 버튼으로 같은 흐름을 시작할 수 있다. 대화 학습 중에는 `Chapter 전체 다시 보기`로 돌아갈 수 있다.

Faceytalk Chapter 2처럼 끝이 확인되지 않은 발췌는 현재 확인된 65–104초만 이어 본다고 화면에 알린다. `목차 확인 중` 영역도 확인된 데이터 범위 안에서만 재생한다.

## 재생속도와 YouTube 화면

0.25배는 제거한다. 화면에는 0.5부터 1.2까지 0.1 간격의 요청 속도를 두며, YouTube가 0.75배를 지원한다고 보고하면 보조 옵션으로 추가한다. YouTube IFrame API가 현재 영상에서 반환한 속도만 활성화하므로 0.6·0.7·0.8·0.9·1.1·1.2배는 해당 영상에서 지원되지 않으면 사용할 수 없다. 실제 적용 속도는 플레이어의 속도 변경 이벤트로 확인하며, 지원하지 않는 값을 선택했을 때 성공했다고 표시하지 않는다. [YouTube IFrame API 재생속도 문서](https://developers.google.com/youtube/iframe_api_reference#getAvailablePlaybackRates).

플레이어는 사용자가 재생 버튼을 누를 때 `loadVideoById`로 시작하고, 화면을 열자마자 불필요하게 cue한 뒤 정지시키지 않는다. 이는 초기 오버레이가 나타날 기회를 줄이지만 YouTube가 자체적으로 표시하는 제목, `동영상 더보기`, 브랜드, 관련 영상 안내를 앱 코드로 완전히 숨길 수는 없다. `rel=0`도 관련 영상을 제거하지 않고 같은 채널의 영상으로 제한한다. [YouTube 플레이어 매개변수 문서](https://developers.google.com/youtube/player_parameters#rel).

## 빈칸 음성

빈칸에서는 선택 단어의 TTS를 제거하고 해당 문장 전체의 YouTube 원본 구간을 반복한다. 학습 길잡이에 실제 영상 플레이어를 표시하며 ‘문장 처음부터 듣기’와 ‘문장 반복 시작/멈추기’를 제공한다. 브라우저가 자동 재생을 막으면 영상 안의 재생 버튼을 안내한다. 소리 퀴즈의 단어 TTS는 유지한다.

영상 ID·콘텐츠 버전·구간 ID·저장된 기준 문장이 모두 현재 자료와 일치할 때만 재생한다. 과거 버전의 단어 기록은 보존하지만, 대응 범위를 확정할 수 없으면 안내하고 다른 문장이나 TTS로 바꿔 재생하지 않는다.

답 제출·다른 단계/단어/화면/계정으로 이동·탭 숨김 시 반복과 준비 중인 자동 재생을 취소한다. 저장 실패나 탭 복귀 후에는 버튼으로 직접 재시작할 수 있다. 재렌더링과 창 종료에서는 이전 문장 플레이어를 해제한다. DB 스키마와 의존성은 변경하지 않았다.

## 검증과 한계

문장 매칭·전체 범위 재생·준비 중 취소·재시작·오래된 비동기 요청 폐기·목차 발췌 표기·원본 참조 보존을 자동 검증한다. `scripts/qa-practice.mjs`에도 실제 문장 플레이어 연결, 단어 TTS 미사용, 제출/탭 이탈 정지 점검을 반영했다.

이번 세션의 자동 계약 테스트에서는 Chapter 전체 재생 범위, 비반복 종료, 시청 완료 전환, 요청 속도와 실제 지원 속도의 분리를 확인했다. 그러나 Playwright 브라우저는 실행 중 종료되었고 브라우저 UI 제어도 정책상 허용되지 않아 실제 화면·실제 음성·YouTube 오버레이·모바일 배치를 확인하지 못했다. 상세 결과는 [VERIFICATION.md](VERIFICATION.md)에 남긴다.
