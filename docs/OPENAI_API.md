# GPT-5.4 뜻풀이와 토큰 한도

GPT-5.4 Responses API 한 번의 응답으로 영어 뜻풀이·품사·한국어 뜻·예문과 해석·어형 및 관련어를 받는다. 화면은 영어 뜻, 한국어 뜻, 예문, 함께 배우는 말로 구분하며 제공자 이름을 학습 내용에 붙이지 않는다. 부모가 저장한 한국어 설명은 우선한다. AI 연결 실패 시 기존 사전과 자동 번역을 사용하며 실패한 패키지는 캐시하지 않는다.

현재 단어와 다음 두 단어를 미리 조회하며 동시에 최대 두 요청을 진행한다. 미리 조회와 화면 조회는 진행 중 요청을 공유한다. 계정 전환 시 취소하고 이전 계정 응답을 버린다. 완전한 패키지만 화면 캐시에 저장한다. 서버 캐시는 `knowledge-v2`로 구분해 이전 뜻풀이 전용 응답을 재사용하지 않으며 토큰 원장은 유지한다. 관련어는 실제 어형 변화·파생어·의미상 관련어를 구분하고 존재하지 않는 품사 변환을 생성하지 않도록 요청한다.

## 서버 설정

Vercel의 OPENAI_KEYS_JSON에는 id와 key를 가진 객체 배열을 저장한다. BLOB_READ_WRITE_TOKEN은 연결된 비공개 Blob 저장소가 제공한다. 두 값은 브라우저 설정이나 정적 ZIP에 넣지 않는다. .env*는 업로드에서 제외한다. 로컬 서버도 같은 환경변수를 제공하면 API를 사용하며 미설정이면 503을 반환한다.

2026-10-06 실제 GPT-5.4 시험에서 key-1·key-2는 성공했고 key-3·key-4는 credit_balance_exhausted 오류로 운영 목록에서 제외했다. 정상 키의 시험 22토큰도 원장에 포함했다. 키 원문과 공급자 오류 본문은 공개 응답이나 로그에 기록하지 않는다.

## 집계와 제한

- America/New_York 날짜 기준 키마다 하루 1,000,000 토큰이다. 이 앱에서 사용한 입력·출력 합계 usage.total_tokens를 누적한다. 다른 앱에서 같은 키로 소비한 토큰은 집계에 포함되지 않는다.
- 원장의 순번으로 키를 번갈아 사용한다. 한도가 부족하거나 비활성·일시 제한 상태인 키는 건너뛴다. 모든 키의 한도가 부족하면 새 생성을 제한한다.
- 호출 전에 요청 UTF-8 바이트 수, 고정 여유분 4,096토큰, 최대 출력 2,048토큰을 예약한다. 사용량과 예약량의 합이 한도 이내인 요청만 실행하므로 예약량보다 잔여량이 적으면 100만에 도달하기 전에도 제한된다.
- 실제 사용량을 받으면 예약을 정산한다. 타임아웃·사용량 누락은 예약을 유지한다. 실제 사용량이 예약보다 크면 해당 키를 비활성화한다.
- 최신 비공개 Blob 원장을 원본에서 읽고 ETag 조건부 쓰기를 사용한다. 오래된 동시 쓰기는 재시도하며 저장소 장애·손상·충돌 지속 시 새 생성을 중단한다. 원본 읽기의 accept-encoding: identity로 압축된 약한 ETag를 피한다.
- 성공한 뜻풀이 최대 500개를 공유 캐시하며 캐시 조회는 OpenAI 토큰을 소비하지 않는다. 정상 응답의 내용 오류는 다른 키로 다시 생성하지 않는다.
- 공개 게스트 API는 신뢰 가능한 Vercel 연결 IP에서 파생한 해시 기준 30회/분·1,000회/일로 제한한다. 로컬에서는 소켓 주소만 사용한다. 식별자나 카운터 확인 실패 시 생성을 중단한다. 분산 IP 공격을 인증으로 차단하는 기능은 아니며 키별 총량 한도가 최종 제한이다.

부모 계정 → AI 뜻풀이 사용량 → 오늘 사용량 확인에서 키 별칭·사용·예약·남은 토큰을 확인한다. 이 조회는 OpenAI를 호출하지 않고 키 원문도 반환하지 않는다.

## 배포와 유지보수

api/와 server/를 포함한 Vercel 배포가 필요하다. GitHub Pages·Cloudflare 정적 ZIP만 올리면 GPT-5.4 서버 경로는 제공되지 않는다. 기본 학습은 정적 배포에서도 동작한다.

추가 npm 의존성 없이 Node 내장 기능을 사용했다. Blob 공식 클라이언트의 버전 12 프로토콜을 별도 모듈에 격리했다. 내부 프로토콜은 바뀔 수 있어 배포 후 원본 읽기·조건부 쓰기 검사를 유지한다. 문제가 생기면 원장 쓰기와 생성을 중단한다. 원장 수동 삭제는 집계를 초기화하므로 운영 중 삭제하지 않는다.
